RESC vs VESC — FOC core and observer

RESC v0.1 · STM32F405 · reference compared: VESC firmware release_7_00 · October 2026
In short. RESC and VESC share the same textbook building blocks: amplitude-invariant Clarke/Park, d/q PI current loop, SVPWM, nonlinear flux observer with PLL. The implementation and the logic around them are RESC's own (an independent audit found no copied FOC code). RESC keeps VESC interfaces (protocol, configuration format, meaning of gains) so VESC Tool, displays and controllers keep working. VESC currently has many more features.

Voltage inputApplied voltage from the modulationAverage of the two duty sets actually applied during the sampled interval, minus a current-sign dead-time term; bridge off: measured phase voltages (flying start)
Speed outputPLL speedDerivative of the PLL angle (ω_int + kp·e). With default PLL gains the integrator alone lagged ~30 % under acceleration in simulation
Health check—Estimated / expected flux ratio monitored: outside 0.5–2 for 20 ms → sync-loss fault
Variants, extrasSeveral observer types, low-speed gain, offset, R/λ temperature compensation, HFIOne observer, no temperature compensation, no HFI yet. Parallel observer comparison is planned but not implemented

6. Status

Not yet in RESC (present in VESC)

  • Field weakening, MTPA, HFI, position control
  • R/λ temperature compensation, observer ↔ sensor blending
  • Parallel observer comparison
  • SPI and sin/cos encoders, dual motor

Validation

  • Simulation: 45/45 closed-loop checks (motor, inverter, Ubox ADC model)
  • Real board: USB, VESC Tool, real-time data, smooth rotation after flux detection
  • To validate on hardware: new R/L procedure, higher power
  • Open: no hardware-independent overcurrent cut on the Ubox board
